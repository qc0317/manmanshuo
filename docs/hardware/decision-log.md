# 硬件决策记录

每项重要决定新增一个条目，不覆盖旧结论。

## ADR-001：第一代优先桌面形态

- 状态：暂定
- 背景：主要场景是孩子在电脑或平板前完成文字表达。
- 决定：第一轮硬件以键盘旁桌面设备为目标。
- 原因：屏幕可读性、麦克风位置、供电和物理按键都更容易验证。
- 重新评估条件：用户测试显示大部分需求发生在离开书桌的场景。

## ADR-002：暂不锁定主控芯片

- 状态：已确认
- 背景：本地识别、云端识别和手机桥接对算力与功耗要求差异很大。
- 决定：在第一轮体验测试完成前，只定义接口和性能指标，不绑定芯片。
- 原因：避免用已有开发板能力反向限制产品体验。

## ADR-003：使用现有 ESP32-S3 小智开发板制作第一台样机

- 状态：已确认
- 日期：2026-09-28
- 决定：第一台可运行样机采用现有 ESP32-S3 N16R8 开发板，不等待定制 PCB。
- 已确认：16 MB Flash、8 MB PSRAM、1.54 英寸 ST7789 TFT、CH340K（COM5）、720 mAh 电池、扬声器、USB-C、预留 UART。
- 原因：设备已经具备显示、联网、供电、声音输出和可下载固件的基础条件，可以快速验证核心交互。
- 板级配置：上游开源工程中的 `xingzhi-cube-1.54tft-wifi`。
- 待确认：实物硬件版本是否与上游引脚表完全一致，以及原固件分区表。
- 保护措施：验证下载模式并备份 Flash 后，才覆盖现有固件。
