# 协作流程

## 每轮迭代

1. 用户提出需求或观察结果。
2. 双方确认需求的真实目的、优先级和边界。
3. 更新产品文档和可展示网页。
4. 对原型、硬件或固件进行实现和验证。
5. 提交到 GitHub，保留变更记录。

## 完成定义

一次需求只有同时满足以下条件才视为完成：

- 需求已经写入相应文档。
- 展示网页反映了当前结论。
- 实现已经通过与风险相称的验证。
- GitHub 中可以追溯到本次变更。

## 决策原则

- 体验证据优先于功能想象。
- 儿童原意和隐私优先于文字质量。
- 硬件指标先于芯片品牌。
- 固件接口先于具体实现。
- 重要结论不只留在聊天中。
